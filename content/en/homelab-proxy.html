Every service you host needs an address and a padlock. Rather than opening one door per service, open one: a reverse proxy. It receives every visitor, holds the HTTPS certificates, and passes each request to the right service inside your network. Ours is Nginx Proxy Manager (NPM): open source, with a web interface, and it renews Let's Encrypt certificates by itself.

What ours does

One small VM (4 GB of RAM, shared with DNS filtering) publishes 19 sites with 35 certificates. This site went online through it today: a container serving the pages, one proxy entry, one certificate, about fifteen minutes.

1. The name

At your domain registrar, create an A record for your domain and one for each subdomain (or a wildcard *), pointing to your public IP address. Check from outside your network that the name resolves before going further.

2. The box

In your internet box, forward ports 80 and 443 to the machine that runs the proxy. Nothing else.

Never forward port 81: it is NPM's administration page. It stays reachable from your home network only.

3. The proxy

On a VM or container with Docker (see Homelab 1), the official compose file, version pinned:

services:
  npm:
    image: jc21/nginx-proxy-manager:2.16.0
    restart: unless-stopped
    ports:
      - "80:80"
      - "81:81"
      - "443:443"
    volumes:
      - ./data:/data
      - ./letsencrypt:/etc/letsencrypt
docker compose up -d

Open http://<proxy-address>:81 from your network. A default administrator account is created on the first start (see the setup page of the official documentation): log in, then change its email and password right away.

4. Publish a service

  1. Hosts → Proxy Hosts → Add Proxy Host.
  2. Domain names: yourdomain.tld, www.yourdomain.tld.
  3. Forward to the service's address and port on your network, for example 192.0.2.10 and 8096.
  4. Tab SSL: request a new Let's Encrypt certificate, tick Force SSL.

Save: Let's Encrypt checks that you own the name through port 80, issues the certificate, and NPM renews it before it expires.

Traps

Do not copy two habits we still have to fix ourselves: the :latest tag (an update arrives the day you restart, unannounced; pin a version and upgrade on purpose) and privileged: true (the proxy does not need full control of the host).

If certificate requests keep failing, stop retrying: Let's Encrypt limits how many identical certificates you can get per week. Fix the cause first, usually port 80 not forwarded or a name that does not resolve yet.

Testing from home and the site does not answer? Some boxes cannot loop back to their own public address. Test from a phone on mobile data before suspecting the proxy.
