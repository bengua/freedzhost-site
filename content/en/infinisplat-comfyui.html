InfiniSplat v2 makes the same promise as AnySplat — photos in, Gaussian splat out — with two differences that matter: it accepts your camera positions when you have them (COLMAP, drone, robot), and it exists as a ComfyUI node, so it plugs into your existing image studio. v2 ("Analyzing and Improving Feed-Forward 3DGS from Any Views", ZJU) mostly hardens robustness when views are few or poorly spread.

What you get. A 312 MB scene.ply in 7.7 seconds of inference from 32 calibrated photos, or in 35 seconds with no poses at all thanks to the Depth-Anything-3 prepass. And an honest answer on VRAM: 13.5 GiB at peak for 32 views.

1. Two paths, one measured truth

There is the command-line path (the infinisplat package, perfect for scripts and agents) and the ComfyUI node path (ComfyUI-InfiniSplat, perfect for wiring the splat into a graph). We tested both. Verdict first: the package works very well; the node requires ComfyUI ≥ 0.39.2 — ours runs 0.37.0 and serves production, so we did not upgrade it for the occasion. You get the full node procedure, and the numbers come from the package.

2. Install the package (the path that always works)

git clone --depth 1 https://github.com/zju3dv/InfiniSplat.git && cd InfiniSplat/InfiniSplat_v2
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python torch==2.14.0 --index-url https://download.pytorch.org/whl/cu130
uv pip install --python .venv/bin/python .
uv pip install --python .venv/bin/python --no-deps \
  "depth-anything-3 @ git+https://github.com/ByteDance-Seed/Depth-Anything-3.git@41736238f5bced4debf3f2a12375d2466874866d"

The --no-deps is intended upstream: InfiniSplat uses Depth-Anything-3's (DA3) network internals pinned to an exact revision, not its application. The weights, 6.6 GB, live on Hugging Face (Edisoneh/InfiniSplat-v2); place config.json and model.safetensors into weights/da3/. The repository also offers a 114-photo sample archive (examples-png.zip, 90 MB) with matching cameras — ideal for a reproducible first run.

3. The measured run

DTU scan 24, 32 views with supplied cameras, on a 16 GB card:

CUDA_VISIBLE_DEVICES=0 .venv/bin/infinisplat --model weights/da3 \
  --images-dir examples/data/dtu_provided/images \
  --cameras examples/data/dtu_provided/cameras.npz \
  --output result_dtu --no-html
load_s=21.4        vram_after_load_mib=6302
inference_s=7.7    vram_peak_mib=13831   n_views=32
export_s=2.2       ply_mb=311.6

And with no poses at all — the da3-pose mode, where DA3 first guesses the cameras and then conditions the reconstruction: 9.9 s of inference for 32 views (13.0 GiB at peak), 35 s in all through the CLI, with a camera_prior.npz saved for reuse. A pose-free mode also exists if you want to skip even that estimate.

VRAM, unvarnished. 13.5 GiB at peak for 32 views: an 8 GB card will not do it as is — cut the view count (--max-views, the API accepts 2 to 50) or go through the ComfyUI node, which samples in chunks precisely to lower the peak. We also watched a run die OOM with 47 MiB free because another process came back to the card mid-flight: on a shared card, just retry, the run costs tens of seconds.

4. The ComfyUI node

The jKaarlehto/ComfyUI-InfiniSplat node (registry: infinisplat, publisher jkaa) does image-to-splat inside a graph: Load Image → InfiniSplat (Image to PLY) → Preview Splat. Three good design ideas: inference runs in an isolated Python environment created by uv run --no-project install.py (nothing pollutes ComfyUI's venv), the node unloads cached ComfyUI models before launching its worker, and the checkpoint lives in models/infinisplat/. Useful parameters: focal_length_mm (30 by default — ComfyUI tensors lose EXIF), gaussian_count (1.5 M), query_chunk_size to tame the memory peak.

cd ~/comfyui/custom_nodes
git clone https://github.com/jKaarlehto/ComfyUI-InfiniSplat.git
cd ComfyUI-InfiniSplat && uv run --no-project install.py
# then restart ComfyUI — read the note below before touching a production instance

Hard requirement: ComfyUI ≥ 0.39.2, because the native splat preview (PreviewGaussianSplat) did not exist before. Ours runs 0.37.0 with a watchdog and render queues: no blind upgrade. Upgrade when production is quiet, or test the node on a second instance (one per card, see the ComfyUI tutorial). On the author's RTX 5090 Laptop (24 GB): optional camera calibration in 2.7 s for 1.03 GiB. Mind the license too: InfiniSplat is free for personal, research and educational use; organisational use requires registration.

5. AnySplat or InfiniSplat?

At similar quality on our examples, choose by workflow: AnySplat is thriftier at peak (7.0 GiB measured for 12 views) and very simple to script; InfiniSplat accepts your cameras when they exist (drone, COLMAP, robot) and has a clean ComfyUI integration. For an agent chaining capture → splat → render, both can be driven from Python in ten lines.

Pitfalls

The Python API caps at 12 views by default (max_views=12) where the CLI accepts 50: a Pipeline()(images) call with 32 photos raises "Upload 2–12 overlapping images". Pass max_views=50.

The Hugging Face weights arrive flat (model.safetensors at the repository root): the CLI wants weights/da3/config.json + weights/da3/model.safetensors. One folder to create, two files to move.

On a RAM-loaded machine (ours holds ComfyUI and its 33 GB of caches), loading the 6.6 GB of weights triggered the OOM killer (earlyoom) twice. Space out heavy jobs, or raise the swap.
