Claude Code est l'agent de code d'Anthropic, dans le terminal. La plupart des gens s'en servent d'une seule façon : avec un abonnement, sur les modèles d'Anthropic. Il peut aussi tourner sur vos propres modèles, pourvu que quelque chose de votre côté parle son protocole. Nous faisons les deux : l'abonnement pour l'exploitation, les modèles locaux pour un junior isolé qui écrit de petits correctifs toute la journée.

1. Sur l'abonnement : l'agent d'exploitation

npm install -g @anthropic-ai/claude-code
claude          # premier lancement : connexion avec votre compte

Donnez-lui un fichier de règles à la racine du dossier de travail, CLAUDE.md. Il est lu à chaque démarrage. Écrivez-y ce qu'un nouveau doit savoir : quelle machine est laquelle, ce qu'il ne faut jamais faire, comment confier du travail aux agents locaux. Gardez-le court et à jour : une règle dépassée mais laissée en place sera appliquée avec une parfaite assurance.

2. Des règles appliquées, pas lues

Une règle écrite dans un fichier est un conseil. Un crochet (hook) est un programme que Claude Code lance avant chaque commande, et qui peut la refuser. Nous avons transformé trois règles en crochets après qu'elles ont été enfreintes une fois chacune :

  • pas de kill par motif de nom (pkill -f) : le motif attrape aussi le propre shell de l'agent ;
  • pas de mot de passe de connexion écrit dans une commande ou un fichier : les secrets passent par un tuyau depuis le coffre (voir les secrets par tuyau) ;
  • pas de modification des fichiers de la distribution, seulement de vos extensions.

Un crochet est un petit script qui lit la commande prévue en JSON sur son entrée et sort en erreur pour la refuser, avec un message que l'agent lit. Vingt lignes de Python suffisent.

3. Sur vos propres modèles : le junior

Claude Code parle l'API Messages d'Anthropic. Une passerelle comme LiteLLM la traduit vers vos modèles locaux. Trois variables suffisent :

export ANTHROPIC_BASE_URL=http://votre-passerelle:4000
export ANTHROPIC_MODEL=coder-local            # le nom du modèle dans la passerelle
export ANTHROPIC_SMALL_FAST_MODEL=coder-local # sinon il réclame un modèle cloud pour les petites tâches
claude -p "Répare le test qui échoue dans tests/test_parse.py. Ne modifie que src/parse.py."

Avant de lancer, vérifiez que le modèle répond sur $ANTHROPIC_BASE_URL/v1/messages : un agent lancé sur une carte qui ne porte rien échoue au bout de plusieurs minutes, pas de quelques secondes.

4. Isoler le junior

Un agent local travaille sans que vous regardiez. Donnez-lui une copie jetable du dépôt, une liste fermée de fichiers, le message de commit et un test à lancer. Il ouvre une demande de fusion ; la CI tourne ; un humain, ou l'agent d'exploitation, lit avant de fusionner. Les tâches courtes reviennent propres ; les longues cassent par fatigue, pas par difficulté.

Pièges

Oubliez ANTHROPIC_SMALL_FAST_MODEL et l'agent envoie ses petites tâches de fond à un nom de modèle cloud que la passerelle ne connaît pas : des erreurs qui ressemblent à une panne.

Ne collez jamais les identifiants de votre abonnement dans l'environnement du junior. Les deux rôles partagent un programme, pas une identité.
