Kimi Code est l'agent de code de Moonshot, sur son propre abonnement, avec un contexte d'un million de jetons. Nous lui confions ce qui est long plutôt que difficile : lire un dépôt entier, une migration sur de nombreux fichiers, une tâche sur laquelle l'agent d'exploitation dépenserait son quota. Avoir deux agents hébergés, c'est aussi en garder un quand l'autre a épuisé son quota.

1. L'installer sur le serveur, pas sur le portable

npm install -g @moonshot-ai/kimi-code
kimi            # premier lancement : connexion au fournisseur géré

Lancez-le dans un multiplexeur de terminal sur la machine qui porte les dépôts, pour que la session survive au portable fermé :

tmux new -s kimi 'kimi'              # sur le serveur, une fois
ssh -t serveur tmux attach -t kimi   # depuis le portable, à tout moment

Un alias d'une ligne sur le portable en fait un seul mot. Depuis un téléphone, la même commande marche dans n'importe quelle appli SSH, par votre réseau privé.

2. Dans un bac à sable quand il travaille seul

Quand une file confie une tâche à Kimi sans que vous regardiez (voir l'hybride par escalade), faites-le tourner dans un bac à sable comme bwrap : le dépôt en lecture-écriture, le reste du système en lecture seule, aucun accès à vos clés. Il ne peut pas casser ce qu'il ne voit pas.

Pièges

La liste d'outils a une limite de taille côté fournisseur. Avec un serveur d'outils qui exposait 170 outils, chaque requête revenait en 400 schema exceeds maximum allowed size, ce qui ressemblait à « modèle injoignable ». Exposez moins d'outils, ou découpez le serveur.

kimi --continue reprend la dernière session du dossier courant. Lancé depuis un autre dossier, il ouvre une session neuve et vide, et vous croyez l'historique perdu. Reprenez toujours depuis le dossier où le travail a commencé.
