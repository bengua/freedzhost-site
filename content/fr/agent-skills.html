Vous expliquez la même procédure à votre agent pour la cinquième fois : comment diagnostiquer un plantage, comment relire une modification sous l'angle sécurité, comment présenter ses réponses pour vous. Une skill l'écrit une fois. L'agent lit sa description d'une ligne au démarrage, et ne charge la procédure complète que quand une tâche correspond.

Ce que vous y gagnez. Des procédures qui s'appliquent toutes seules, sans coût permanent : retirer une skill et trois sous-agents n'a pas fait bouger notre plancher de contexte mesuré d'un seul jeton. Une trentaine de skills installées ici, utilisées tous les jours.

1. Ce qu'est une skill

~/.claude/skills/diagnose-crash/
├── SKILL.md          # nom, description (le déclencheur), puis la procédure
├── reporting.md      # pages en plus, lues seulement si besoin
└── scripts/          # aides facultatives que la procédure appelle
---
name: diagnose-crash
description: >
  Diagnose why a program crashed on this machine, from a systemd-coredump
  core dump. Use when a process segfaulted or aborted, or when asked why
  an application crashed. Triggers: crash, segfault, core dump.
---
# Diagnosing a crash
Work from evidence. Start with `coredumpctl info <pid>` ...

C'est la description qui décide quand la skill se déclenche : dites ce qu'elle fait et les mots que contiendra une demande. Le corps est la procédure, écrite pour un collègue.

2. Celles que nous utilisons

  • Des réponses taillées pour un lecteur TDAH : l'action suivante d'abord, des étapes numérotées, l'état rappelé à chaque tour, une chose concrète à faire à la fin. Active dans chaque session.
  • Le diagnostic de plantage à partir d'un core dump : les faits d'abord, l'épuisement des ressources écarté avant d'accuser le programme.
  • La rétro-ingénierie avec preuves (voir REA) : analyser, prouver, questionner, puis coder.
  • Un harnais de revue de sécurité : une skill d'aiguillage, une chaîne de revue, et une base de connaissances par classe de faille (injection, XSS, SSRF, traversée de chemin, secrets, situations de concurrence…), chargée seulement pour la classe recherchée.
  • La vidéo comme une page web (HyperFrames) : une explication, une promo ou un clip sous-titré s'écrit comme une composition HTML avec des attributs de temps, se prévisualise dans le navigateur et se rend en vidéo. Une famille de skills couvre l'animation, le son, les images clés et un catalogue de blocs prêts ; une skill média transforme musiques, bruitages, icônes et voix en fichiers locaux, avec un registre de leurs sources.
  • Les schémas : quarante-cinq types de graphiques en HTML autonome avec SVG intégré, qui demandent d'abord vos couleurs (voir les schémas en code).

3. Skill ou outil ?

Une procédure à plusieurs bonnes réponses (comment découper un projet, comment formuler une réponse) est une skill : le modèle exerce son jugement. Une vérification à une seule bonne réponse (ce fichier valide-t-il, ce test passe-t-il) est un outil : un programme qui répond pareil à chaque fois. Ne demandez pas un verdict à une skill (voir BMAD avec de petits modèles).

Pièges

Une description vague ne se déclenche jamais, une description gourmande se déclenche partout. Écrivez les déclencheurs comme vous formulez vraiment vos demandes, et testez avec trois vraies.

Lisez une skill communautaire avant de l'installer, comme n'importe quel programme : elle peut dire à l'agent de lancer des commandes.
