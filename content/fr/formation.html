La formation freedzhost : apprendre à développer son code, assisté par l'IA, sur sa machine — pas à dépendre d'une IA qui code à ta place.

La doctrine

Coder avec l'IA, c'est bien. Développer son propre code assisté par l'IA, c'est plus fort.

Coder avec l'IA (le "vibe coding") : tu décris, l'IA génère, tu colles. Ça marche pour un prototype un dimanche. Mais le jour où ça casse — et ça casse — tu débogues un code que tu n'as pas écrit, que tu ne comprends pas, et que l'IA ne comprend plus non plus à la troisième génération.

Développer assisté par l'IA : tu poses l'architecture, tu écris les décisions, tu lis chaque diff — et l'IA fait ce qu'elle fait le mieux : la vitesse, les tests, la documentation, les variantes. Le modèle propose, le code décide, et toi tu arbitres. C'est cette posture qu'on enseigne, parce que c'est celle qui tient sur la durée : un code qu'on comprend se répare, un code qu'on subit se repaie.

Les prérequis

Aucun niveau développeur exigé. En revanche, il faut les bases — et chacune est déjà couverte par un tuto gratuit du site :

  • Un terminal et ne pas en avoir peur — lire une erreur, lancer une commande, comprendre ce qu'est un chemin de fichier.
  • Git, juste le nécessaire — sauvegarder, revenir en arrière, lire un changement. (Tuto Forgejo CI.)
  • Savoir ce qu'est un serveur chez soi — une machine qui tourne, un port, une IP locale. (Matériel, Homelab Proxmox.)
  • Un modèle local qui répond — le premier ollama run ou llama.cpp. (Tuto first model.)
  • La curiosité de lire ce que l'IA écrit — c'est le prérequis qu'on ne peut pas tutoriel-iser ; le reste s'apprend.

Chaque module de la formation commence par vérifier ces bases avec toi, et renvoie vers le tuto gratuit qui les répare si elles manquent.

Et si le code te rebute ?

Pas envie — ou pas le temps — d'apprendre les langages ? Ce n'est pas une fin, c'est un chemin différent, et il est honorable. Les outils no-code self-hébergés permettent déjà presque tout :

  • n8n — l'automatisation par blocs : brancher des services, des modèles locaux, des webhooks, sans écrire une ligne. (Déjà couvert par nos tutos.)
  • PocketBase / Baserow — une base de données et une auth avec une vraie interface d'admin : ton espace membre, tes listes, tes contenus.
  • Appsmith / Tooljet — des interfaces internes par glisser-déposer, branchées sur tes données.
  • Home Assistant — la domotique entière en automatisations visuelles.
  • WordPress / statique + formulaires — pour publier sans développer.

Notre position honnête : le no-code t'emmène loin, et la formation t'y emmène aussi — plusieurs modules sont entièrement jouables en no-code. Mais chaque notion de code que tu acceptes de comprendre (pas écrire : comprendre) décuple ce que le no-code peut faire pour toi. Un prompt qui sait ce qu'est une API, un webhook ou une base de données obtient de l'IA des résultats qu'un prompt sans vocabulaire n'obtiendra jamais. On te propose donc les deux portes d'entrée, et elles se rejoignent.
