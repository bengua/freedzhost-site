Cette série remplace un par un les services que vous louez : stockage, photos, bureautique, recherche, mots de passe. Il leur faut un endroit où vivre. Cet endroit, c'est Proxmox VE : un hyperviseur libre et open source qui transforme une machine en plusieurs serveurs isolés, chacun facile à sauvegarder, à figer en instantané et à jeter.

Ce que fait tourner le nôtre

Mesuré sur notre nœud (Proxmox VE 9.2, 16 threads, 30 Go de RAM, un SSD NVMe de 2 To pour les invités, un disque de 8 To pour les sauvegardes) :

InvitéRôleRAM
VMproxy inverse avec HTTPS, filtrage DNS4 Go
VMsuite bureautique, moteur de recherche, gestionnaire de tâches9 Go
VMforge de code et sa CI6 Go
VMautomatisation et domotique4 Go
VMbase de connaissance (recherche dans nos notes)2 Go
VMcoffre privé, tenu à part3 Go
conteneurun petit modèle juge sur processeur—

Un vieux PC de bureau ou un mini PC suffit pour commencer. Ce qui compte : la RAM (16 Go minimum, 32 Go confortable), un SSD pour les invités, et un second disque pour les sauvegardes.

1. Installer

  1. Téléchargez l'ISO de Proxmox VE sur proxmox.com/downloads.
  2. Écrivez-la sur une clé USB. Sous Linux : sudo dd if=proxmox-ve.iso of=/dev/sdX bs=4M status=progress, où /dev/sdX est la clé (vérifiez deux fois avec lsblk : dd efface ce que vous lui désignez).
  3. Démarrez la machine sur la clé et suivez l'installateur : disque cible, pays, mot de passe root, e-mail, et une adresse IP fixe sur votre réseau.
  4. Depuis un autre ordinateur, ouvrez https://<cette-adresse>:8006 et connectez-vous en root. Le navigateur prévient au sujet du certificat : il est auto-signé, c'est normal sur votre propre réseau.

2. Le canal de mises à jour gratuit

Par défaut, Proxmox pointe vers son dépôt « enterprise », qui demande un abonnement payant : les mises à jour échouent avec une erreur. Pour un homelab, passez sur le canal gratuit pve-no-subscription, comme le documente Proxmox.

Désactivez le dépôt enterprise : dans /etc/apt/sources.list.d/pve-enterprise.sources, ajoutez la ligne

Enabled: no

Puis créez /etc/apt/sources.list.d/proxmox.sources :

Types: deb
URIs: http://download.proxmox.com/debian/pve
Suites: trixie
Components: pve-no-subscription
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg

Et mettez à jour :

apt update && apt full-upgrade

Proxmox ne recommande pas ce canal pour des serveurs de production : ses paquets sont moins testés que ceux du dépôt enterprise. Pour la maison, c'est le bon choix ; si Proxmox fait tourner votre entreprise, prenez l'abonnement, il finance aussi le projet.

3. Votre premier conteneur

Les conteneurs (LXC) sont plus légers que les machines virtuelles : parfaits pour un service chacun. Téléchargez un modèle, puis créez le conteneur :

pveam update
pveam available --section system | grep debian
pveam download local <le nom du modèle affiché ci-dessus>

Puis dans l'interface web : Create CT, choisissez le modèle, donnez-lui 1 CPU, 512 Mo de RAM et 8 Go de disque pour commencer. Les trois s'agrandissent plus tard.

4. Votre première machine virtuelle

Pour un service qui a besoin de son propre noyau (Docker avec beaucoup de conteneurs, un autre système d'exploitation) : envoyez une ISO dans local → ISO Images, puis Create VM. Même règle : commencer petit, agrandir ensuite.

5. Les sauvegardes, avant tout le reste

Dans Datacenter → Backup, programmez une sauvegarde nocturne de chaque invité vers un second disque. Puis restaurez-en une, une fois, pour vérifier que ça marche.

Une sauvegarde sur le même disque que les invités n'est pas une sauvegarde : elle meurt avec ce disque. Une sauvegarde jamais restaurée est un espoir, pas une sauvegarde.

Un piège que nous évitons

N'ouvrez jamais le port 8006 sur Internet. Pour administrer Proxmox de l'extérieur, passez par un réseau privé comme Tailscale ou WireGuard : la page d'administration reste invisible depuis Internet.
