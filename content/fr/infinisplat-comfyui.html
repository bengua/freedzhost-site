InfiniSplat v2 fait la même promesse qu'AnySplat — des photos en entrée, un nuage de gaussiennes en sortie — avec deux différences qui comptent : il accepte vos positions de caméra quand vous les avez (COLMAP, drone, robot), et il existe en nœud ComfyUI, donc branchable sur votre studio d'images existant. La v2 (« Analyzing and Improving Feed-Forward 3DGS from Any Views », ZJU) soigne surtout la robustesse quand les vues sont peu nombreuses ou mal réparties.

Ce que vous y gagnez. Un scene.ply de 312 Mo en 7,7 secondes d'inférence à partir de 32 photos calibrées, ou en 35 secondes sans aucune pose grâce au prépassage Depth-Anything-3. Et une réponse honnête sur la VRAM : 13,5 Gio au pic pour 32 vues.

1. Deux chemins, une seule vérité mesurée

Il y a le chemin ligne de commande (le paquet infinisplat, parfait pour des scripts et des agents) et le chemin nœud ComfyUI (ComfyUI-InfiniSplat, parfait pour câbler le splat dans un graphe). Nous avons testé les deux. Verdict d'abord : le paquet marche très bien ; le nœud exige ComfyUI ≥ 0.39.2 — le nôtre est en 0.37.0 et sert la production, donc nous ne l'avons pas mis à jour pour l'occasion. On vous donne la procédure complète du nœud, et les chiffres viennent du paquet.

2. Installer le paquet (le chemin qui marche à coup sûr)

git clone --depth 1 https://github.com/zju3dv/InfiniSplat.git && cd InfiniSplat/InfiniSplat_v2
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python torch==2.14.0 --index-url https://download.pytorch.org/whl/cu130
uv pip install --python .venv/bin/python .
uv pip install --python .venv/bin/python --no-deps \
  "depth-anything-3 @ git+https://github.com/ByteDance-Seed/Depth-Anything-3.git@41736238f5bced4debf3f2a12375d2466874866d"

Le --no-deps est voulu par l'upstream : InfiniSplat utilise les entrailles réseau de Depth-Anything-3 (DA3) épinglées à une révision précise, pas son application. Les poids, 6,6 Go, sont sur Hugging Face (Edisoneh/InfiniSplat-v2) ; placez config.json et model.safetensors dans weights/da3/. Le dépôt propose aussi une archive de 114 photos d'exemple (examples-png.zip, 90 Mo) avec leurs caméras — idéale pour un premier run reproductible.

3. Le run mesuré

Scène DTU scan 24, 32 vues avec caméras fournies, carte de 16 Go :

CUDA_VISIBLE_DEVICES=0 .venv/bin/infinisplat --model weights/da3 \
  --images-dir examples/data/dtu_provided/images \
  --cameras examples/data/dtu_provided/cameras.npz \
  --output result_dtu --no-html
load_s=21.4        vram_after_load_mib=6302
inference_s=7.7    vram_peak_mib=13831   n_views=32
export_s=2.2       ply_mb=311.6

Et sans aucune pose — le mode da3-pose, où DA3 devine d'abord les caméras puis conditionne la reconstruction : 9,9 s d'inférence pour 32 vues (13,0 Gio au pic), 35 s en tout via la CLI, avec un camera_prior.npz sauvegardé pour être réutilisé. Le mode pose-free existe aussi si vous ne voulez même pas cette estimation.

La VRAM, sans maquillage. 13,5 Gio au pic pour 32 vues : une carte de 8 Go n'y arrivera pas en l'état — réduisez le nombre de vues (--max-views, l'API en accepte de 2 à 50) ou passez par le nœud ComfyUI, qui échantillonne par morceaux pour justement baisser le pic. Nous avons aussi vu un run mourir en OOM à 47 Mio libres parce qu'un autre processus est revenu sur la carte en cours de route : sur une carte partagée, relancez, le run coûte quelques dizaines de secondes.

4. Le nœud ComfyUI

Le nœud jKaarlehto/ComfyUI-InfiniSplat (registre : infinisplat, éditeur jkaa) fait du image-to-splat dans un graphe : Load Image → InfiniSplat (Image to PLY) → Preview Splat. Trois bonnes idées de conception : l'inférence tourne dans un environnement Python isolé créé par uv run --no-project install.py (rien ne pollue le venv de ComfyUI), le nœud décharge les modèles ComfyUI avant de lancer son worker, et le checkpoint vit dans models/infinisplat/. Paramètres utiles : focal_length_mm (30 par défaut — les tenseurs ComfyUI perdent l'EXIF), gaussian_count (1,5 M), query_chunk_size pour dompter le pic mémoire.

cd ~/comfyui/custom_nodes
git clone https://github.com/jKaarlehto/ComfyUI-InfiniSplat.git
cd ComfyUI-InfiniSplat && uv run --no-project install.py
# puis redémarrer ComfyUI — voyez la note ci-dessous avant de toucher à une instance en production

Exigence ferme : ComfyUI ≥ 0.39.2, car l'aperçu natif de splats (PreviewGaussianSplat) n'existait pas avant. Le nôtre tourne en 0.37.0 avec un watchdog et des files de rendu : pas de mise à jour à l'aveugle. Mettez à jour quand la production est calme, ou testez le nœud sur une seconde instance (une par carte, voir le tuto ComfyUI). Chez l'auteur, une RTX 5090 Laptop (24 Go) : calibration caméra optionnelle en 2,7 s pour 1,03 Gio. Notez aussi la licence : l'usage personnel, recherche et éducatif d'InfiniSplat est libre, l'usage en organisation demande un enregistrement.

5. AnySplat ou InfiniSplat ?

À qualité proche sur nos exemples, choisissez par le workflow : AnySplat est plus frugal au pic (7,0 Gio mesurés pour 12 vues) et très simple à scripter ; InfiniSplat accepte vos caméras quand elles existent (drone, COLMAP, robot) et a une intégration ComfyUI propre. Pour un agent qui enchaîne capture → splat → rendu, les deux se pilotent en Python en dix lignes.

Pièges

L'API Python plafonne par défaut à 12 vues (max_views=12) quand la CLI en accepte 50 : un Pipeline()(images) avec 32 photos lève « Upload 2–12 overlapping images ». Passez max_views=50.

Les poids Hugging Face arrivent à plat (model.safetensors à la racine du dépôt) : le CLI veut weights/da3/config.json + weights/da3/model.safetensors. Un dossier à créer, deux fichiers à déplacer.

Sur une machine chargée en RAM (la nôtre tenait ComfyUI et ses 33 Go de caches), le chargement des 6,6 Go de poids a déclenché deux fois le OOM-killer (earlyoom). Espacez les gros jobs, ou montez le swap.

Pour aller plus loin

Le module « capture 3D » de la formation entre dans le dur : calibrer ses caméras avec COLMAP pour le mode provided, choisir entre da3-pose et pose-free, et convertir un splat en mesh texturé pour un moteur de jeu.
