Demandez à un modèle comment installer un outil, il répond avec la version vue pendant son entraînement, peut-être vieille de deux ans, avec une parfaite assurance. Une recherche sur le web aide une fois. Un knowledge pack garde la réponse vérifiée : ce qui a été contrôlé, d'où ça vient, comment le tester sur votre machine, et jusqu'à quand s'y fier.

Ce que vous y gagnez. Des agents qui cessent de reconstruire les procédures de mémoire : ils lisent un pack dont les affirmations sont sourcées, dont les étapes ont tourné sur la machine cible, et qui vous prévient tout seul quand un fait est périmé.

1. Cinq règles

  1. Une affirmation sans source datée n'entre pas dans un pack.
  2. Une procédure sans assertion exécutable n'est pas une procédure.
  3. Un pack reste en draft tant qu'un passage sur la vraie machine n'a pas produit de preuves.
  4. Les affirmations expirent : chacune porte une durée de vie, et une tâche planifiée ouvre une issue quand elle est dépassée.
  5. Rien ne fusionne au rouge.

2. À quoi ressemble un pack

packs/install-forgejo-runner/
├── kp.md          # en-tête, affirmations sourcées, la procédure en gabarit
├── assert.sh      # assertions par phase : PASS/FAIL, code de sortie non nul sur FAIL
└── evidence/      # ce qu'a affiché le passage de validation : versions, journaux d'assertions

3. Sa vie

besoin → recherche par un modèle capable, avec accès au web
       → demande de fusion, statut : draft        (CI : lint + shellcheck)
       → passage sur le terrain par un humain     (assert.sh, phase par phase)
       → preuves versionnées, « validated_on » rempli
       → relecture humaine → fusion = validé
       → tâche de péremption → issue → nouvelle vérification → mise à jour

Trois rôles, jamais mélangés : l'auteur (un modèle avec une recherche fraîche) écrit et ne fusionne jamais ; l'exécutant (n'importe quel modèle local) utilise un pack et ne le modifie jamais ; l'humain fait le passage sur le terrain et approuve.

Pièges

Une assertion qui se contente de chercher un mot dans un fichier prouve que le mot est là, pas que l'étape a marché. Vérifiez ce que fait le système : une version affichée, un port qui répond, un service qui tourne.

Gardez les preuves même quand elles sont ennuyeuses. Le jour où le pack expire, c'est à l'ancienne sortie qu'on compare.
