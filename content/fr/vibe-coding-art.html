Début 2025, Andrej Karpathy a donné un nom à une façon de travailler que beaucoup avaient commencé à pratiquer : le vibe coding. Vous décrivez ce que vous voulez en langage courant, une IA écrit le code, vous le lancez, vous regardez, vous demandez des changements, et vous cessez tout simplement de lire le code. Pour un serveur en production, c'est un risque. Pour un artiste, c'est une porte : la distance entre une idée et une image en mouvement n'a jamais été aussi courte.

Ce que vous y gagnez. Une carte des usages créatifs du vibe coding (visuels, shaders, musique, mouvement, interaction), la façon de les pratiquer avec vos propres modèles locaux et sans abonnement, et la règle simple que nous suivons pour que les esquisses restent un plaisir et que rien de fragile ne finisse en production.

1. Ce qui change pour les créateurs

Le creative coding existe depuis des décennies : écrire des programmes dont le résultat est une image, un son, un mouvement. Il a toujours eu une barrière : il fallait apprendre le langage avant de créer quoi que ce soit. Le vibe coding abaisse cette barrière. Le savoir-faire passe de la syntaxe à l'intention et au jugement : décrire une ambiance avec précision, reconnaître ce qui fonctionne, demander le bon changement.

2. Les déclinaisons dans l'art numérique

  • Les visuels génératifs : des esquisses en p5.js ou Processing, décrites plutôt que tapées : « des particules qui dérivent comme de la cendre, montent lentement, couleurs de la braise au gris ». Changez la graine, obtenez une série.
  • Les shaders : de petits programmes pour la carte graphique qui calculent chaque pixel, l'art de Shadertoy. Réputés durs à écrire à la main, étonnamment abordables par la description et l'itération.
  • La musique codée en direct : des environnements comme Strudel, TidalCycles ou Sonic Pi, où un motif de texte est un rythme. Un modèle propose un motif, vous le modifiez en direct, sur scène si vous voulez : la scène algorave le fait depuis des années.
  • Les visuels en direct : de la synthèse vidéo dans le navigateur à la manière de Hydra, branchée par le code et jouée comme un instrument.
  • Le motion design en code : une vidéo écrite comme une composition HTML, minutée et animée, puis rendue. Nos clips explicatifs utilisent cette approche (voir les skills créatives).
  • Les œuvres interactives et les mascottes : le moteur d'animation de notre FoxBot, ses planches et ses humeurs ont été construits avec des agents, en décrivant des comportements plutôt qu'en dessinant des images (voir le chat du homelab pour la même idée).
  • Les générateurs d'images, de vidéo et de musique : pas du code, mais la même posture : décrire, regarder, affiner (voir le studio).

3. Le pratiquer en local

  1. Ouvrez un agent de code sur votre propre modèle (OpenFox) dans un dossier vide.
  2. Demandez un seul fichier HTML avec p5.js et une seule esquisse ; ouvrez-le dans le navigateur.
  3. Décrivez ce que vous voyez et ce que vous voulez à la place, en sensations et en contraintes, pas en code : « plus lent », « plus d'espace pour respirer », « les couleurs d'un matin d'hiver ».
  4. Gardez les graines et les versions qui vous plaisent : une esquisse est une série, pas une image unique.

Un petit modèle local suffit pour des esquisses de quelques dizaines de lignes. Les programmes longs et structurés sont là où il peine ; c'est aussi là que le vibe coding cesse d'être le bon outil.

4. Où nous traçons la limite

Le vibe coding est parfait quand le prix d'une erreur est une image ratée. Il est dangereux quand le code tourne sans surveillance, détient des données ou fait face à internet : un modèle écrit du code plausible qui n'a peut-être jamais tourné, et « ça a l'air bien » n'est pas un test. Notre règle, tirée de la doctrine déterministe : du vibe pour les esquisses et l'art ; lire, tester et mesurer pour tout ce qui tourne seul.

Pièges

Les droits comptent toujours. Générer « à la manière de » un artiste vivant, ou à partir de son travail, soulève des questions auxquelles l'outil ne répond pas pour vous. Construisez votre propre style ; citez ce qui vous inspire.

Une page web faite en vibe coding et publiée telle quelle peut contenir une clé, une route de débogage ou un formulaire ouvert. Avant de publier, lisez-la une fois (voir l'audit).
