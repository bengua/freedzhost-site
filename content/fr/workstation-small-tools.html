Tous les outils n'ont pas besoin d'un serveur. Ces trois-là sont des scripts uniques, bibliothèque standard Python seulement, qui répondent chacun à une question de tous les jours : où sont mes anciennes conversations, à quel point mon agent est près d'oublier, et qu'est-ce qui a bougé sur mes machines.

Ce que vous y gagnez. Tout votre historique de chat IA en fichiers que vous pouvez lire, chercher et indexer ; une jauge de contexte pour un agent local, qu'aucun abonnement hébergé ne vous montre ; et un « qu'est-ce qui a changé » hebdomadaire pour chacune de vos machines.

1. Votre historique Claude.ai, en fichiers : claude-archive

L'export officiel (Paramètres → Confidentialité → Exporter les données) est complet mais en JSON brut. Un script en fait une archive utilisable :

python3 claude_archive.py ~/Téléchargements/data-XXXX.zip -o ./claude-archive
  • un fichier Markdown par conversation, dans l'ordre des dates ;
  • chaque bloc de code extrait en vrai fichier source ;
  • une liste des pièces jointes à récupérer à la main, puisque l'export ne les contient pas ;
  • un manifeste avec les comptes d'entrée et de sortie : rien n'est perdu en silence.

Sans réseau, sans dépendance. Idéal pour nourrir votre propre recherche dans vos notes.

2. Une jauge de contexte dans la barre d'état : openfox-omarchy

Un agent hébergé montre ce qui reste de votre abonnement. Un agent local n'a pas d'abonnement ; sa vraie limite, c'est le contexte, qui se remplit et retombe à chaque compaction. Un petit script lit le stockage des sessions d'OpenFox et écrit l'enregistrement que le widget des agents d'Omarchy dessine déjà, à côté de Claude Code et Codex :

install -m 755 openfox-usage ~/.local/bin/openfox-usage
openfox-usage      # puis un minuteur utilisateur toutes les dix minutes

Quand vous ajoutez un fournisseur dans les réglages du widget, listez-les tous : donner providers remplace la liste par défaut, donc oublier claude masque Claude.

3. L'inventaire par scan, pas par déclaration : parc

Ansible pousse un état et l'oublie ; les outils de supervision observent sans comparer. parc part de ce qui existe : vous scannez vos machines, et il vous dit ce qui a bougé.

./parc.py scan local portable serveur   # instantané de chaque machine
./parc.py diff                          # ce qui a changé depuis
./parc.py compare portable serveur      # écarts entre deux machines
./parc.py since 7j                      # ce qui a bougé cette semaine
./parc.py export-ansible                # inventaire et playbook de réconciliation

En lecture seule par défaut ; apply n'installe qu'après une confirmation tapée à la main, et ne désinstalle jamais. diff sort en 1 quand une machine s'écarte, il tient donc dans une tâche cron.
